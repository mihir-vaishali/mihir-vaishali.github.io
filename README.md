# Mihir & Vaishali — Wedding Invitation

Generated by the Wedding Admin Panel.

## Run locally

```bash
npm ci
npm run dev
```

`npm ci` installs the exact versions recorded in `package-lock.json`, so this
site builds the same way today and in a year. Use `npm install` only when you
intend to update dependencies.

## Quick start

```bash
npm run setup
```

That installs dependencies and makes the first commit, then prints the exact
commands to publish — it detects whether you have the GitHub CLI and adjusts.
Safe to re-run: every step is skipped if already done.

Prefer to do it by hand? See below.

## Deploy to Vercel

Never commit `node_modules` — Vercel installs during its own build, and the
included `.gitignore` already excludes it. Running `npm install` locally is
only for previewing the site yourself with `npm run dev`.

**Via GitHub — best if you will update the site later**

```bash
git init -b main
git add .
git commit -m "Wedding invitation"
git remote add origin <your-new-repo-url>
git push -u origin main
```

Then import the repository at [vercel.com/new](https://vercel.com/new). Every
later push redeploys automatically.

**Via the Vercel CLI — quickest, no repository needed**

```bash
npm run deploy
```

The first run asks you to log in (choose *Continue with GitHub*). Note that a
bare `npx vercel` publishes a *preview* URL; `npm run deploy` passes
`--prod` so you get the live one.

Either way Vercel detects Vite automatically: build `npm run build`, output
`dist`. **This site needs no environment variables.**

## Changing the content later

For small edits — a date, a name, a venue — edit
[`src/config/site.js`](src/config/site.js) directly and push; Vercel rebuilds
on its own. Regenerating from the admin panel is only necessary when you are
changing photos or adding ceremonies.

## Editing content later

All copy, dates, ceremonies and image paths live in
[`src/config/site.js`](src/config/site.js). Photos are in `public/images/`.
